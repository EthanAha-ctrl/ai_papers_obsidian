给 data 一套身份证系统 + 黄页 + 快递协议 + 说明书, 让机器能像人查 Wikipedia 一样, 自动找到、拿到、读懂、复用 data。
你花了三天扒 source code 想复现某个 dataset 的 cleaning pipeline, 才发现 README 写着 "see internal repo, not public"。
2016 年一群荷兰、德国、英国 informatician 看不下去了, 写了这 15 条 principles。
科学界也需要一个 Google + DNS + HTTP + robots.txt 的 stack。FAIR 是把 web 这套设计哲学搬到 data world。

## 2. F (Findable) - data 的身份证

没 ID, 一切免谈
FAIR F1 就是逼你给每个 dataset 一个 globally unique persistent ID (DOI/Handle), 别人引用时写 `doi:10.5072/XXXX`, 而不是 "ImageNet from the website we downloaded on March 2024"。
F4 (registered in searchable resource): 你的 dataset 不能只在自己 lab 的 git repo 里躺着, 要 push 到 Zenodo / DataCite / Google Dataset Search。这就像 webpage 要被 Googlebot crawl 才能搜到。否则就 invisible。

## 3. A (Accessible) - data 的快递协议

F 解决 "知道它存在", A 解决 "怎么拿到它"。

**A1 的关键**: 拿 data 要走 standardized protocol。不能是这样: "email the author and ask politely"。那样的话 data 是 human-actionable 的, 机器帮不了你。机器要能 `curl -L https://doi.org/10.5281/zenodo.XXX` 拿到 bytes。

**A1.1 的 "open, free, universally implementable"**: 这条是历史教训。2010 年很多 repository 用私有协议 SOAP、custom API, 一旦 funding 断了, client 没人维护, data 就废了。所以强制 HTTP/HTTPS, 这是唯一能存活 30 年的 protocol。

**A1.2 Authentication**: FAIR ≠ Open。临床数据、基因数据、Indigenous 文化数据, 必须能 authenticated access。但要做到机器识别身份 (OAuth2/OpenID Connect/SAML), 然后自动授权。这一条是为了让 "受控但 FAIR" 可行, 否则学术界没人敢 open sensitive data, 又会退回 silo。

**A2 - metadata 比 data 活得久**: 这条很 archival。data 文件太大, 存储费贵, 十年后可能删掉。但 metadata (一个 JSON, 几 KB) 应该永远留着, 告诉后人 "这里曾经存在过一个 dataset, 叫 XXX, DOI XXX, 2024 年被撤回因为 consent 问题"。这就是 **tombstone record**。考古学的逻辑。

## 4. I (Interoperable) - data 之间能互相 link

Interoperability 是 FAIR 中最难也最反直觉的一条。人话讲: **两个 dataset 不能只在 PDF 里互相 cite, 要在 machine-readable level 上 cross-link**。

举例, 你研究 protein-protein interaction, 用 UniProt 的 protein ID。你的 dataset 引用 protein 时, 不要写 "human p53" (free text), 要写 `uniprot:P04637` (URI)。这样机器能 hop: 你的 dataset → UniProt entry → 外部 annotation → publication。这就是 **Linked Data**。

技术上实现是 RDF triple: (subject, predicate, object), 三个都是 URI。但 you don't need to care about RDF 太细节, 只需要记住一点: **让所有的 "名字" 都是 URL**。这是 Tim Berners-Lee 2006 年提出的 Linked Data 5-star model 的核心。FAIR I1-I3 基本就是这个的 rephrasing。

Reference: [Linked Data 5-star model](https://www.w3.org/DesignIssues/LinkedData.html)

**I3 "qualified references"**: 你的 metadata 说 "this dataset was derived from ImageNet", 这不够。要说 `prov:wasDerivedFrom <https://doi.org/10....>`。"qualified" 的意思是: 关系类型 + 关系对象, 都要明确。不能只说 "related to"。

## 5. R (Reusable) - data 别人能放心用

R 是 FAIR 的终极目的, 也是 ML practitioners 最该 care 的部分。

**R1.1 License**: data 没 license = 不可商用且 copyright 全留给你。你 Karpathy 训练 GPT 的时候, 如果在 dataset card 看到 "license: unknown", 你慌不慌? FAIR 强制每个 dataset 有 machine-readable license, 比如 `CC-BY-4.0` (SPDX identifier)。这样企业 compliance team 一眼能判断能不能用。

**R1.2 Provenance**: "provenance" 是 archival science 借来的词, 意思是 "这个东西的来历"。W3C 搞了个 PROV-O ontology, 形式化描述: Entity A was generated by Activity B, which was associated with Agent C, used Entity D。说白了就是 data 的 git log, 但是 cross-resource 的。

对 ML: 你训练一个 model, dataset 是别人 tokenize 过的, tokenize script 又来自另一仓库。三个 artifact 都要有 PID, 三者关系要 link。这就是 HuggingFace Hub 想做的事, 尽管做得不完整。

**R1.3 Community standards**: 不同领域有自己的 metadata standard。Genomics 必须 MIAME-compliant, brain imaging 必须 BIDS, 不然 community tooling 用不了。FAIR 在这里说: 别自己造 schema, 用 community 已有的, 这样别人工具链能直接接上。

Reference: [PROV-O W3C Recommendation](https://www.w3.org/TR/prov-o/), [BIDS specification](https://bids.neuroimaging.io/)

## 6. 把 FAIR 当 data engineering 的 CI/CD

我自己的 mental model: **FAIR 是 data engineering world 的 CI/CD**。

Software engineering 有 CI/CD 是因为 code 会腐烂, 没有 test pipeline 项目就会 crash。FAIR 出现是因为 data 会腐烂, 没有 stewardship pipeline scientific record 就会 rot。

FAIR-ification 的 pipeline, 形式化一点, 就是给每个 data asset $D$ 跑 15 个 check:

$$
\text{FAIRScore}(D) = \sum_{i \in \{F1,...,R1.3\}} c_i \cdot \mathbb{1}[D \text{ satisfies } i]
$$

每个 $c_i$ 是 community-agreed weight。这就像 linter, 每条 principle 是一条 lint rule。只不过 FAIR 的 lint rule 需要 infrastructure 支撑 (DOI registry、metadata schema、repository), 单靠 lab 自己做不了。

Reference: [F-UJI FAIRness evaluator](https://www.f-uji.net/)

## 7. ML 视角: FAIR 与 LLM 训练 data 的张力

你训练 LLM 的时候遇到的 dataset, 99% 不 FAIR。原因:

- Common Crawl 一坨 HTML, 没 PID, 没 license, 没 provenance → 违反 F1, A1, R1.1, R1.2
- Tokenized corpus 一个 binary blob, 不能 link 到原始 URL → 违反 I3
- 没有 standard schema 描述 "this is a tokenized web dataset" → 违反 R1.3

LLM 实际上让 FAIR 更难了。GPT-4 paper 写 "trained on a combination of publicly available data and licensed data", 从 FAIR 角度看, 这是 not even wrong - 没有任何 reproducible 路径。

这就是为什么 [Bender et al. 2021 "On the Dangers of Stochastic Parrots"](https://dl.acm.org/doi/10.1145/3442188.3445922) 强调 data provenance。也是为什么 HuggingFace 推出 [BigScience ROOTS](https://github.com/bigscience-workshop/data) 试图做 LLM 训练 data 的 FAIR-ification, 但结果也只覆盖了 498 source documents, 远不够 trillion tokens 级别。

我个人的直觉: **FAIR 1.0 是 batch-oriented dataset 假设下的设计**, 对 streaming data、continuous training、federated data 这类 dynamic 场景不够用。下一代会引入时间维度、版本维度、distribution 维度, 类似 git 之于 svn 的演进。

## 8. FAIR ≠ Open, 这是关键

很多人误以为 FAIR 就是 open data。不是。FAIR 让 closed data 也能 FAIR, 只要 closed data 走 authenticated API、metadata 是 open 的。这一点对 biomedical 领域非常重要 - 患者基因数据不能 open, 但能 FAIR, 通过 dbGaP authenticated access。

类比: GitHub 上 private repo 也是 "FAIR" 的 - 有 PID (repo URL), 有 metadata (README), 有 protocol (git over HTTPS), 有 provenance (git log), 有 license (LICENSE file)。只是 access 要 auth。这就是 FAIR 想要的所有 data 都达到的状态。

## 9. 为什么 FAIR 难推广

**Incentive 不对**: FAIR-ify 一个 legacy dataset 要花几天甚至几周, 但 paper 不算作者工作量, tenure committee 也不 care。所以大家都说 FAIR 好, 但实际做的少。

**Cost 沉淀, benefit 分散**: 我花精力给 dataset 加 metadata, 受益的是几千里外用我 dataset 的人。这是 public good 问题, 需要 Funding agency 强制 (像 NIH DMSP 2023, Horizon Europe DMP requirement)。

**Tooling 不统一**: 同一 dataset, F-UJI 给 0.7, FAIRshake 给 0.4, 自己 evaluator 给 0.9。让 researcher 不知道往哪儿努力。

Reference: [NIH Data Management & Sharing Policy](https://sharing.nih.gov/data-management-and-sharing-policy), [Ten simple rules for making data FAIR](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1006900)

## 10. 我会怎么用 FAIR

如果今天我要 ship 一个 dataset (比如一个 instruction-tuning corpus), 我会:

1. 上 [Zenodo](https://zenodo.org/) 或 [HuggingFace Hub](https://huggingface.co/datasets), 拿 DOI
2. 写一份 dataset card, 用 [Datasheets for Datasets](https://arxiv.org/abs/1803.09010) template
3. 在 README 顶部加 JSON-LD block (Schema.org/Dataset), 让 Google Dataset Search crawl 到
4. 明确 license, 优先 CC-BY-4.0 或 CC0
5. 用 [DVC](https://dvc.org/) 做 data versioning, 配合 git 给 provenance
6. 每个 example 加 source URL field (尽量), 这样有 I3 qualified reference
7. 跑一遍 [F-UJI](https://www.f-uji.net/) 检查分数, 至少 > 0.7

这一套流程下来, 你的 dataset 在科学界就基本可引用、可 reproducible、可商用判断。比起发 arXiv paper 描述 dataset, FAIR-ification 让 dataset 本身成为 first-class scientific object, 能独立被 cited (有 DOI = 能进 Crossref = 能进 Google Scholar)。

## 最后的直觉

FAIR 的本质, 是把 "dataset" 从一个**离散的、靠人脉传播的、不可验证的民间物**升级成一个**有 PID、有 protocol、有 metadata、有 license 的 first-class digital citizen**。它对应于 web 把零散的 FTP server 升级成可被 Google 检索的 hyperlink 网络的那次跃迁。

差别在于 web 是 1995 年靠商业驱动自下而上演进出来的, FAIR 是 2016 年靠学术共同体自上而下倡议出来的。自上而下的标准推广速度永远慢, 所以 FAIR 在 2026 年仍处于 "大家都认可, 但没几个真做到" 的阶段。下一波 push 大概率是 regulatory (像 GDPR 之于 privacy), 时机可能是 AI training data 的某个大 lawsuit 之后。

# FAIR Guiding Principles 深度解析

## 1. 历史背景与动机

2016年, Mark Wilkinson 等人在 *Scientific Data* 期刊发表了 "The FAIR Guiding Principles for scientific data management and stewardship" 这篇 landmark paper。其核心动机在于解决 scientific data ecosystem 面临的几个根本性问题:

- **Data silos**: 各 institution、各 lab 的 data 彼此孤立
- **Reproducibility crisis**: 大量 published research 无法被 reproduced
- **Machine-actionability 不足**: 大部分 digital assets 仍需 human curation 才能 discovered 与 consumed

FAIR 的设计哲学把 **machine-actionability** 置于核心位置, 因为现代 data 的 volume (TB/PB 量级)、complexity (multi-modal, heterogeneous)、velocity (real-time streams) 已远远超过 human curation 能力上限。

Reference: [Wilkinson et al. 2016, Scientific Data](https://www.nature.com/articles/sdata201618)

## 2. FAIR 的四个维度 - 技术实现拆解

### 2.1 Findable (F1-F4)

**F1: Globally unique and persistent identifier (PID)**

技术实现的核心是 **Persistent Identifier (PID)** 体系, 主要包括:

- **DOI** (Digital Object Identifier): 由 Crossref / DataCite 维护, 使用 Handle System 底层
- **Handle System**: `10.5072/ABC123` 中的 `10` 是 naming authority, `5072` 是 prefix, `ABC123` 是 suffix
- **ARK** (Archival Resource Key): 由 California Digital Library 维护, URL 可读
- **ORCID**: researcher-level PID, `https://orcid.org/0000-0002-1825-0097`
- **ROR** (Research Organization Registry): institution-level PID

**F2/F3: Rich metadata + 显式包含 identifier**

需要 metadata schema 既 rich 又 machine-readable。主流 schemas:

- **DataCite Metadata Schema 4.x**: 21 mandatory/optional fields, 包括 `creator`, `title`, `publicationYear`, `resourceType`, `identifier`
- **Schema.org/Dataset**: JSON-LD 格式, 被 Google Dataset Search 索引
- **DCAT (Data Catalog Vocabulary)**: W3C recommendation, RDF-based

**F4: Searchable resource**

关键 infrastructures:
- [Google Dataset Search](https://datasetsearch.research.google.com/) (基于 Schema.org)
- [DataCite Search](https://search.datacite.org/)
- [OpenAIRE Explore](https://explore.openaire.eu/)
- [Zenodo](https://zenodo.org/) (CERN 维护)

### 2.2 Accessible (A1-A2)

**A1.1: Open protocol**

HTTP/HTTPS 是事实标准。REST API 与 OAI-PMH (Open Archives Initiative Protocol for Metadata Harvesting) 用于 scholarly repositories。

**A1.2: Authentication & Authorization**

- **OAuth 2.0**: authorization framework, RFC 6749
- **OpenID Connect**: identity layer on top of OAuth 2.0
- **SAML 2.0**: federated identity, 学术界常用 InCommon、eduGAIN
- **API keys / JWT** (JSON Web Token): stateless token, 由 `header.payload.signature` 构成

**A2: Metadata persistence even when data gone**

这一条来自 archival science, 对应 **OAIS** (Open Archival Information System) reference model (ISO 14721:2012)。**Tombstone records** 是常见做法 - data 被 withdraw 后, metadata (含撤稿原因) 仍然保留。

### 2.3 Interoperable (I1-I3)

**I1: Formal knowledge representation language**

核心是 **RDF** (Resource Description Framework) 三元组模型:

$$\text{triple} = (s, p, o)$$

其中:
- $s$ (subject): URI-reference, 标识被描述的 resource
- $p$ (predicate): URI-reference, 标识 property/relation (来自 ontology)
- $o$ (object): URI-reference 或 literal value

构建于 RDF 之上的 stacks:

- **RDFS** (RDF Schema): class/subclass hierarchy
- **OWL** (Web Ontology Language): DL-based, 支持 `owl:Class`, `owl:ObjectProperty`, `owl:DatatypeProperty`
- **SHACL** (Shapes Constraint Language): RDF data validation
- **JSON-LD**: JSON 的 RDF 序列化, Web 友好

**I2: FAIR vocabularies**

- **SKOS** (Simple Knowledge Organization System): thesauri, classification schemes
- **OBO Foundry**: 涵盖 GO (Gene Ontology), CHEBI, UBERON 等 biomedical ontologies
- **LOV** (Linked Open Vocabularies): [lov.linkeddata.es](https://lov.linkeddata.es/)

**I3: Qualified references**

"Qualified reference" 指通过 URI 显式 link 其他 (meta)data, 而非 free-text citation。技术上是 `owl:sameAs`、`skos:exactMatch`、`dcterms:isPartOf` 等 predicate。

### 2.4 Reusable (R1-R1.3)

**R1.1: License**

- **CC-BY 4.0**: attribution required, 最常用
- **CC0**: public domain dedication
- **ODC-BY / ODbL**: Open Data Commons licenses
- **SPDX identifiers**: `CC-BY-4.0` 是 SPDX standardized identifier, machine-readable

**R1.2: Provenance**

**W3C PROV** standard (PROV-O ontology), 核心实体:

$$
\text{Entity} \xleftarrow{\text{wasGeneratedBy}} \text{Activity} \xleftarrow{\text{wasAssociatedWith}} \text{Agent}
$$

PROV-O 通过 `prov:wasGeneratedBy`, `prov:wasDerivedFrom`, `prov:used` 等 properties 表示 data lineage。具体实现如 [ProvStore](https://provenance.ecs.soton.ac.uk/)、[Whole Tale](https://wholetale.org/)。

**R1.3: Community standards**

domain-specific:
- Genomics: **MIAME** (Minimum Information About a Microarray Experiment), **GEO** format
- Proteomics: **MIAPE**, deposited to **PRIDE**
- Neuroscience: **BIDS** (Brain Imaging Data Structure), 你 Karpathy 做 neural net 也间接用到 fMRI data 经常是 BIDS 格式
- ML: **Datasheets for Datasets** (Gebru et al. 2018), **Model Cards** (Mitchell et al. 2019)

Reference: [Datasheets for Datasets](https://arxiv.org/abs/1803.09010), [Model Cards](https://arxiv.org/abs/1810.03977)

## 3. FAIRness 量化评估 - 一个公式视角

FAIR 的可测量性一直有争议。多个 frameworks 试图量化 FAIRness:

### 3.1 RDA FAIR Data Maturity Model

13 metrics, 每条 FAIR principle 对应 1-2 metrics, 评分 0-5。

### 3.2 FAIR Evaluator (FAIRsharing)

由 Wilkinson 本团队开发, 采用 [FAIRsharing](https://fairsharing.org/) registry 评估 community standards compliance。

### 3.3 FAIRshake

NIH funded, 用于 biomedical digital objects 的 FAIRness scoring。其评分公式可以形式化为:

$$\text{FAIRness}(o) = \frac{1}{|\mathcal{M}|} \sum_{m \in \mathcal{M}} w_m \cdot \mathbb{1}[o \models m]$$

其中:
- $o$ = 被 evaluate 的 digital object
- $\mathcal{M}$ = metric 集合 (例如 FAIR 15 个 sub-principles)
- $w_m \in [0, 1]$ = metric $m$ 的 weight (community 定义)
- $\mathbb{1}[o \models m] \in \{0, 1\}$ = indicator function, 表示 object $o$ 满足 metric $m$
- $|\mathcal{M}|$ = metric 总数 (用于归一化)

更精细的 continuous scoring 会引入 **partial credit**:

$$s_m(o) \in [0, 1], \quad \text{FAIRness}(o) = \sum_{m} w_m s_m(o) \Big/ \sum_m w_m$$

**Practical caveat**: 不同 evaluators (FAIR Evaluator, F-UJI, FAIRshake) 给同一 dataset 的分数差异巨大, 这反映 FAIR principles 本身的 ambiguity。Cardoso et al. 2020 实证研究显示同一 dataset 在不同 tools 上分数范围 0.2 - 0.95。

Reference: [F-UJI tool](https://www.f-uji.net/), [FAIRshake](https://fairshake.center/), [Cardoso et al. 2020](https://doi.org/10.5281/zenodo.4080347)

## 5. FAIR 在 ML/AI 领域的应用 - 与你的工作相关

你 Andrej 在 OpenAI、Tesla 都做过 large-scale data。FAIR 在 ML 语境下的关键对应:

### 5.1 Dataset Cards / Datasheets

Hugging Face 的 [Dataset Cards](https://huggingface.co/docs/hub/datasets-cards) 实际是 FAIR R1 在 ML 领域的 instantiation。含:
- Dataset description, composition, collection process
- Preprocessing, uses, distribution, maintenance
- License (R1.1), provenance (R1.2)

### 5.2 Model Cards + Datasheets 的链式 FAIRity

ML training pipeline 中, model、dataset、code 三个 entity 互相 reference:

$$
\text{Model}_\theta \xleftarrow{\text{trained-on}} \text{Dataset}_D \xleftarrow{\text{derived-from}} \text{RawData}_R
$$

每条 edge 都应该有 qualified reference (I3), 每个节点都有 PID (F1)。这正是 **MLflow**, **Weights & Biases**, **Hugging Face Hub** 试图解决的事情。

### 5.3 Reproducibility 在 LLM 时代的挑战

LLM training data (例如 GPT-4 的 corpus) 几乎不可能 fully FAIR-ify, 因为:
- 数据来自 Common Crawl 等混合来源, provenance 难追溯 (违反 R1.2)
- Preprocessing script 不公开 (违反 A1)
- 没有 persistent identifier 给每个 training example (违反 F1)

学界正在推 [Datasheets for Large Language Models](https://arxiv.org/abs/2303.13942), 试图制定 LLM-specific FAIR 标准。

### 5.4 FAIR 与 Foundation Models 的张力

FAIR 假设 data 是离散、可标识的 digital object。但 foundation model 时代:
- Training data 是几 trillion tokens 的 stream, 不构成 "dataset" 单位
- Model checkpoint 本身是 PB 量级 binary, metadata 难承载其所有 attributes

可能的演进方向是 **dynamic FAIR**: data 在 streaming、continuous training 语境下的 FAIR-ification 标准。相关工作: [Data Version Control (DVC)](https://dvc.org/), [LakeFS](https://lakefs.io/), [Delta Lake](https://delta.io/)。

## 6. FAIR 的批评与局限

### 6.1 "FAIR ≠ Open"

FAIR 明确区分 accessible 与 open。Closed 数据可以 FAIR (如临床数据通过 authenticated API 访问)。但实践中 FAIR 经常被误读为 open data 同义词, 这导致 implementation 矛盾。

### 6.2 CARE Principles 的补充

Indigenous data communities 提出 [CARE Principles](https://www.gida-global.org/care) (Collective benefit, Authority to control, Responsibility, Ethics), 弥补 FAIR 的技术取向忽略 cultural、sovereignty 维度的问题。

### 6.3 评估 Inter-rater reliability 问题

研究中给同一 dataset, 不同 FAIR expert 评分 Pearson $r \approx 0.6$, Krippendorff's $\alpha \approx 0.5$, 显示主观性很强。Reference: [Bahram et al. 2020](https://doi.org/10.1371/journal.pcbi.1007874)。

### 6.4 Cost 与 incentive mismatch

FAIR-ifying 一个 legacy dataset 估计成本 \$500-\$5000 USD, 但 researcher 几乎没有 promotion incentive 做 FAIR-ification。这是 systemic 问题, 非 technology 能解决。

- **Horizon Europe**: 强制 DMP, Open Access, FAIR data

## 8. 一个具体 FAIRification Pipeline 示例

假设你有一个 image classification dataset 想做 FAIR-ify, 步骤:

1. **Identifier assignment**: 在 Zenodo 上传, 获得 DOI `10.5281/zenodo.XXXXXXX`
2. **Metadata enrichment**: 用 DataCite Schema 填 `creator` (ORCID), `title`, `keywords` (MeSH or CV terms)
3. **License**: 选 CC-BY 4.0, SPDX `CC-BY-4.0`
4. **Provenance**: 用 PROV-O 描述从 raw images 到 annotated dataset 的 transformation chain
5. **Interoperability**: 用 Schema.org/Dataset JSON-LD, 提交 sitemap 给 Google Dataset Search
6. **Validation**: 用 [FAIRdat](https://www.fairdat.org/) 或 F-UJI 跑评分, 期望 > 0.8


## 9. 总结与我的 Intuition

把 FAIR 的本质提炼成一句话: **FAIR 是把 web hyperlink 的设计哲学扩展到 scientific data ecosystem**。Tim Berners-Lee 的 Linked Data 5-star model (2006) 是 FAIR 的精神前身:

$$
\star\star\star\star\star = \text{on web} + \text{machine-readable} + \text{non-proprietary} + \text{RDF/URIs} + \text{linked}
$$

FAIR 在此基础上加入了:
- Persistence (DOI 体系)
- Domain standards (R1.3)
- License (R1.1) - legal layer
- Authentication (A1.2) - access control

其局限在于, 当 data 体量超出 PID 体系承载能力 (LLM training corpus 量级), 或当 "dataset" 概念本身被解构 (continuous streaming data), FAIR 的 ontology 假设会失效。下一代的 data stewardship 标准必然要回应这些挑战, 估计会在 2027-2030 之间出现一个 "FAIR 2.0" 或 "FAIR for AI" 标准。
