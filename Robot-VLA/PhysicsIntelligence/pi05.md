# π0.5 用人话讲

## 一句话版本

Physical Intelligence 做了个 robot 大脑叫 π0.5，它能在**从没见过的家庭里**自己收拾厨房、整理卧室，一干就是 10 到 15 分钟。之前所有 VLA 都做不到这一点，π0.5 证明了一件事：让 robot 在新环境干活，关键靠**从各种异构数据里迁移知识**，单纯堆 robot data 没用。

参考：https://pi.website/blog/pi05

---

## 为什么这件事难？

之前的 VLA 比如 RT-2、OpenVLA、π0 在训练环境里看着挺猛，换个家就歇菜。原因很简单——真实世界太复杂：

- 厨房布局千变万化，抽屉把手形状各异
- 物体类别无穷无尽，训练时见过的盘子跟测试时的盘子长得就不一样
- 长程任务需要连续做几十个动作，中间任何一步失败就全崩

靠"多收集 robot data 覆盖所有场景"这条路走不通——你不可能给每个家庭都录 400 小时数据。所以必须找别的办法。

---

## 核心洞察：人怎么干活，robot 就该怎么干活

你到一个新厨房能收拾，是因为你有一辈子积累的知识可以迁移：
- 见过类似抽屉，知道怎么拉开
- 听过"把盘子放水槽"这句话，知道啥意思
- 见过盘子长啥样，知道该抓哪儿
- 收拾过别的房间，知道先做什么后做什么

π0.5 的核心 idea 就是让 robot 也吸收这种**多源异构知识**。他们混了 5 大类数据训同一个 transformer：

| 数据类型 | 缩写 | 教会了什么 |
|---|---|---|
| Mobile manipulator 数据 | MM | 400 小时目标 robot 平台直接经验 |
| 多环境固定臂数据 | ME | 跨家庭场景的 manipulation primitives |
| 实验室 cross-embodiment | CE | 跨机器人的基础抓放能力 |
| 高级 subtask 标注 | HL | 任务如何分解成步骤 |
| Web 图文数据 | WD | 物体语义、视觉概念、属性 |
| Verbal instruction（后期） | VI | 人类用语言指挥机器人干活的 demonstration |

---

## 最反直觉的发现：97.6% 训练数据不是目标 robot 的

pre-training 阶段，**只有 2.4% 的样本来自真正要用的 mobile manipulator**。剩下 97.6% 都是别的机器人、web 图文、lab 数据。但最终模型在全新家庭里干 mobile manipulation 干得很好。

这是 transfer learning 在 robotics 的胜利——只要 training recipe 设计得当，知识可以从各种乱七八糟的源头迁移到目标任务上。

公式上体现就是统一到 sequence modeling：

$$\pi_\theta(a_{t:t+H}, \hat\ell \mid o_t, \ell) = \pi_\theta(a_{t:t+H} \mid o_t, \hat\ell) \cdot \pi_\theta(\hat\ell \mid o_t, \ell)$$

- $o_t$：observation，包含图像 $I_t^i$ 和 robot 本体感受 $q_t$
- $\ell$：人类的高层 prompt（如 "clean the kitchen"）
- $\hat\ell$：模型自回归输出的文本（subtask 或 VQA 答案）
- $a_{t:t+H}$：长度为 $H+1=50$ 的连续 action chunk

不管输入是图像、文本、action，统统 tokenize 后喂给同一个 transformer。这框架天然适合混合数据训练。

---

## 模型设计的两个巧思

### 巧思一：同一个模型既能"思考"又能"动手"

π0.5 用 hierarchical inference：每一步先输出 subtask 文本，再根据 subtask 输出 action。

举例：用户说 "clean the kitchen"，模型看到场景后：
1. 先吐出一句话："pick up the plate"
2. 然后基于这句话输出 50 步连续 action 控制机械臂去抓盘子
3. 抓完再吐下一句："put it in the sink"
4. 继续 action...

这跟 chain-of-thought 在 LLM 里一个道理，只不过这里 thought 是 subtask，action 是真去执行。关键 insight：**同一个 transformer 干两件事**，不需要像 SayCan 那样用一个 LLM 当 planner + 另一个 policy 当 executor。

为什么这招 work？因为训练数据里 HL subtask 和 action 是配对的——模型同时学"说什么 subtask 合适"和"这个 subtask 对应什么 action"。两边互相强化。

参考 chain-of-thought：https://arxiv.org/abs/2201.11903

### 巧思二：离散 token + 连续 flow matching 混着训

这是论文最工程化最巧妙的部分。两种 action 表示各有优缺点：

| 表示 | 优点 | 缺点 |
|---|---|---|
| FAST discrete token | 训练快、language following 强、跟 VLM 共享 framework | 推理要 autoregressive 解码 50 步，慢 |
| Flow matching 连续 action | 10 步 denoising 即可推理，能表达 multi-modal action 分布 | 从头训慢，要专门的 action expert |

π0.5 的解决方案：**两套都训，用 attention mask 隔离开**。

总损失：
$$\mathcal{L} = \mathbb{E}\Bigl[ \underbrace{H(x_{1:M}, f_\theta^\ell(o_t, \ell))}_{\text{cross-entropy on text + FAST tokens}} + \alpha \underbrace{\|\omega - a_{t:t+H} - f_\theta^a(a_{t:t+H}^{\tau,\omega}, o_t, \ell)\|^2}_{\text{flow matching on action expert}} \Bigr]$$

变量解释：
- $a_{t:t+H}^{\tau,\omega} = \tau \cdot a_{t:t+H} + (1-\tau)\omega$：interpolated state，$\tau$ 是时间索引从 0（纯噪声）到 1（真值），$\omega \sim \mathcal{N}(0, I)$ 是高斯噪声
- $f_\theta^\ell$：VLM backbone 输出 text token logits
- $f_\theta^a$：action expert（300M 参数小 transformer）输出 flow vector field
- $\alpha$：trade-off 系数，pre-training 设 $0$（只训 FAST），post-training 设 $10.0$（同时训）

关键 mask 设计（见论文 Fig. 18）：
- FAST token 可以 attend 到 VLM prefix，也可以 auto-regressive attend 前面的 FAST token
- Flow matching action expert 可以 attend 到 VLM prefix 和自己内部，**但不能 attend FAST token**（防止作弊）
- VLM 不能 attend action expert（信息单向流：VLM → action expert）

这样两套 action 表示在同一个模型里共存但独立训练。pre-training 用 FAST 把 VLM 训得对 action 有概念，post-training 加 flow matching 让模型学会实时连续控制。

---

## 训练流程：先杂后精

### Stage 1: Pre-training（280k steps，α=0）

混所有数据训，只做 next-token prediction（包括 FAST action token）。这阶段目标是让模型吸收广博知识——物体语义、动作 primitive、任务结构、跨 embodiment 经验。

这阶段的好处：用 VLM 训练成熟工具链，compute efficient，language following 能力强。

### Stage 2: Post-training（80k steps，α=10）

筛掉 CE 数据，聚焦 mobile manipulation。新增 VI（verbal instruction）数据——人类专家用语言指挥机器人干活的 demonstration。同时引入随机初始化的 action expert，开始训 flow matching。

这阶段好处：让模型学会实时连续 action 生成，且 VI 数据教模型怎么合理分解任务。

### 数据归一化的细节

不同机器人 action 维度不一样，他们统一到最大维度，低维 zero-pad。每个 action 维度按 1% / 99% quantile 归一化到 $[-1, 1]$（用 quantile 抗 outlier）。prompt 里加 `<control mode> joint/end effector <control mode>` 区分控制模式。

---

## 机器人系统：极简 end-to-end

两种移动双臂平台，硬件配置：
- 2 个 6-DoF 臂 + 平行夹爪
- 4 个相机：forward / backward / 左右腕各一
- 全向轮式底盘
- Torso lift（1D 或 2D）
- 总共 18-19 DoF state 和 action 空间

控制方式极其朴素：
- π0.5 直接输出 target pose（臂、夹爪、torso）+ target base velocity
- 50 Hz 频率，action chunking
- 底层就简单 PD 控制器跟踪
- **没有轨迹规划，没有碰撞检测，完全 end-to-end**

这点挺震撼——传统 robotics 这类任务要写一堆 motion planner + collision checker，π0.5 一个 transformer 全包了。

## 实验结果中最重要的几个结论

### 结论 1：在 3 个全新真实家庭里稳定成功

测了厨房 + 卧室两类任务，每任务 10 次 trial，task completion 都不错。任务时长 2-5 分钟，涉及多阶段操作。比如把 4 个盘子逐个放进水槽，把衣服放进洗衣篮。

### 结论 2：训练环境数从 3 涨到 104，性能稳步提升

更关键的对照实验：
- **104 个家庭训练 + 完整 co-training** 的模型
- **直接把测试家庭放进训练集**的 baseline 模型

两者性能**几乎一样**！这意味着 co-training recipe 完全 bridge 了 generalization gap。

而如果只用 104 个家庭的 robot data（去掉 web/HL co-training），性能显著差。说明光靠 robot data scale 完全不够。

### 结论 3：各种数据源的 ablation

去掉 ME 或 CE（cross-embodiment 数据）：mock home 性能显著下降
去掉 WD（web data）：mock home 任务影响不大，但 **OOD 物体识别大幅下降**

直觉解释：
- cross-embodiment 教的是"怎么抓怎么放"这种通用 manipulation skill
- web data 教的是"这是漏斗、那是药瓶"这种物体语义知识
- 两者互补，缺一不可

per-task 分析更有意思：
- Items in Drawer 任务：WD/ME/CE 都重要（需要识别物体 + 操作）
- Dishes in Sink 任务：ME/CE 重要，WD 不重要（主要是 manipulation）
- Laundry / Make Bed：cross-embodiment 重要，其他不敏感

### 结论 4：High-level inference 的 ablation

最反直觉的发现：**implicit HL（训练含 HL 数据但不显式推理）性能接近 explicit HL**！

说明训练数据中的 subtask 标注让模型隐式学会了任务结构，相关信息已经编码在 hidden state 里。显式 inference 只是锦上添花。

而 **GPT-4 zero-shot 当 HL policy 性能最差**——证明 VLM 知识必须用 in-domain robot data fine-tune 才能用于 control。

VI 数据虽只占 11% 但极重要，去掉性能显著下降。

## 我的 intuition 构建

### 1. VLA 框架的统一性是成功基石

为什么 5 种异构数据能混训？因为 VLA 把所有东西都 tokenize 成 sequence。图像、文本、action chunk、object detection bbox、subtask label，统统是 token sequence。transformer 天然适合这种 mixed-modality next-token prediction。

这点很像 GPT 用同一套 next-token prediction 既能写代码又能做数学题——只要数据 tokenize 化，transformer 就能学。

### 2. 离散 token 是 "语言"，连续 flow 是"肌肉"

可以把 FAST token 看成"动作的语言描述"，把 flow matching 看成"真正的肌肉控制信号"。pre-training 学语言，post-training 学肌肉，两层组合。这跟人类学技能有点像——先在脑子里用语言描述步骤，再训练肌肉执行。

### 3. "Language demonstration" 是新范式

VI 数据本质是人类用语言指挥机器人——这相当于 high-level policy 的 imitation learning 数据。以前监督 high-level reasoning 很难，因为"什么时候该说啥 subtask"很难标注。VI 提供了一种自然的方式：人类实时"教"机器人怎么分解任务。

这跟 LLM 的 instruction tuning 异曲同工——都是用人类示范教模型"该说什么"。

### 4. Co-training recipe > 数据 scale

最重要 takeaway：未来 VLA 的进步更多来自 training recipe 设计（哪些数据混、怎么混、何时混），而不是单纯堆数据。π0.5 证明 400 小时 mobile manipulator 数据 + 聪明的 co-training 就能搞定全新家庭的长程任务，这远比 Open X-Embodiment 那种堆几万小时数据的路子性价比高。

### 5. 这套框架可扩展性极强

论文结尾说 limitation 时提到 prompt 复杂度受数据限制、context window 有限等。但框架本身扩展空间巨大：
- 加 video pre-training（教模型时间维度的常识）
- 加 sim data（教物理 prior）
- 加 RL post-training（修复 persistent failure modes）
- 扩展到 humanoid、四足、灵巧手

---

## 一句话再总结

π0.5 是 VLA 走向真正 open-world deployment 的里程碑——它证明了一个 end-to-end 学习的机器人能在全新家庭里干 10 分钟以上的复杂家务活。秘诀不在 robot data 规模，在 training recipe——把 cross-embodiment、web data、subtask prediction、verbal instruction 这些异构知识源通过 sequence modeling 框架统一训练，让知识跨模态、跨 embodiment 迁移。设计上两个核心巧思：同一个 transformer 同时做 high-level reasoning 和 low-level action；用 attention mask 混合离散 FAST + 连续 flow matching 两套 action 表示。

# π0.5: Open-World Generalization for VLA Models 深度解析

## 一、核心问题与动机

π0.5 解决的痛点：现有 VLA 模型在「训练环境内」表现惊艳，但迁移到「未见过的新家庭」执行 long-horizon 任务（清理厨房/卧室，10-15 分钟）时仍然失效。作者的假设：要实现这种 wild generalization，光靠 brute-force scale up robot data 不够，必须让模型从**异构多源数据**中迁移知识——包括其他机器人形态、网络图文数据、高级语义预测、人类口头指令等。这本质上是把 "knowledge transfer" 这一经典 ML 思想在 VLA 的 sequence modeling 框架下重新设计。

**关键反直觉发现**：在 pre-training 阶段，**97.6% 的训练样本不来自 mobile manipulator 本身**——而是来自其他机器人平台、web data 等。最终模型依然能在全新家庭中完成 mobile manipulation 任务。这是大规模 cross-embodiment + cross-modal transfer 成功的实证。

## 二、模型架构（详解）

### 2.1 分解式输出分布

模型同时输出文本 token（高级 subtask 或 VQA 答案）和连续 action chunk：

$$\pi_\theta(a_{t:t+H}, \hat{\ell} \mid o_t, \ell) = \pi_\theta(a_{t:t+H} \mid o_t, \hat{\ell}) \cdot \pi_\theta(\hat{\ell} \mid o_t, \ell)$$

变量含义：
- $o_t = [I_t^1, \ldots, I_t^n, q_t]$：观察向量，包含 $n$ 个相机图像 $I_t^i$ 和本体感受状态 $q_t$（关节角、夹爪位姿、躯干提升位姿、底盘速度）
- $\ell$：用户的高级任务 prompt，例如 "put away the dishes"
- $\hat{\ell}$：模型自回归生成的 token 化文本输出，既可能是预测的 subtask（"pick up the plate"），也可能是 web 数据中 VQA 的答案
- $a_{t:t+H}$：长度为 $H+1=50$ 的 action chunk

**关键设计**：action 分布 $\pi_\theta(a \mid o_t, \hat\ell)$ 只依赖 $\hat\ell$，**不直接依赖原始 prompt $\ell$**。这强制模型走 hierarchical 路径——必须先"思考"出 subtask，再决定 action。这类似于 chain-of-thought，但发生在同一个 transformer 内。

### 2.2 Transformer forward 表达

$$y_{1:N} = f\bigl(x_{1:N}, A(x_{1:N}), \rho(x_{1:N})\bigr)$$

变量：
- $x_{1:N}$：$N$ 个 multimodal input tokens，每个 $x_i$ 可以是：
  - text token：$x_i^w \in \mathbb{N}$（词表索引）
  - image patch：$x_i^I \in \mathbb{R}^{p \times p \times 3}$（经 vision encoder 编码后进入 transformer）
  - flow matching 中间 denoising action：$x_i^a \in \mathbb{R}^d$
- $\rho(x_i)$：路由函数，根据 token 类型选择 encoder + expert weights（MoE 思想）
- $A(x_{1:N}) \in [0,1]^{N \times N}$：attention matrix，定义 token 间可见性

输出分两部分：
- $y_{1:M}^\ell$：text token logits，用于采样 $\hat\ell$
- $y_{1:H}^a$：action expert 输出，线性投影后得到连续 action
- 约束 $M + H \leq N$，并非所有 output 都参与 loss

### 2.3 关键创新：混合离散/连续 action 表示

纯离散 token（FAST）训练快、language-following 强；纯 flow matching 表达力强、推理适合实时控制。π0.5 用 attention mask 同时训练两套表示。

总损失：
$$\mathcal{L} = \mathbb{E}_{\mathcal{D}, \tau, \omega}\Bigl[ H\bigl(x_{1:M}, f_\theta^\ell(o_t, \ell)\bigr) + \alpha \bigl\| \omega - a_{t:t+H} - f_\theta^a(a_{t:t+H}^{\tau,\omega}, o_t, \ell) \bigr\|^2 \Bigr] \tag{1}$$

变量细节：
- $H(\cdot, \cdot)$：cross-entropy（text tokens 与预测 logits 之间），**包括 FAST encoded action tokens**
- $a_{t:t+H}^{\tau,\omega} = \tau \cdot a_{t:t+H} + (1-\tau)\omega$：interpolated state（flow matching）
- $\tau \in [0,1]$：flow matching 时间索引，0 表示纯噪声，1 表示真实 action
- $\omega \sim \mathcal{N}(0, I)$：标准高斯噪声
- $f_\theta^a$：action expert 网络（小 transformer，300M 参数），训练目标预测 flow vector field $\omega - a$
- $\alpha \in \mathbb{R}$：trade-off 系数，pre-training 设 $\alpha=0$（纯 FAST），post-training 设 $\alpha=10.0$（同时启用 FAST + flow）

**Attention mask 的精妙设计**（Fig. 18）：
- VLM prefix（images, prompt, proprioceptive state）：full bidirectional attention
- FAST action tokens：attend VLM prefix + auto-regressive on prior FAST tokens
- Action expert embeddings：attend VLM prefix + 互相 attend，**不 attend FAST tokens**（防止信息泄漏）
- VLM 不 attend action expert（**信息单向流动**：VLM → action expert）

这个 mask 设计让两套 action 表示可以共存但独立训练。pre-training 阶段 $\alpha=0$，模型是标准 next-token predictor，FAST tokens 提供丰富的 action 监督信号。post-training 加入 action expert，初始化为随机权重，通过 flow matching 学习连续 action 生成。

### 2.4 Action expert 的 timestep 注入

不同于 π0 直接把 $\tau$ 与 noise action 融合，π0.5 使用单独的 MLP 投影 $\tau$，再通过 adaptive RMSNorm 注入 action expert 每一层：

$$\text{swish}\bigl(W_2 \cdot \text{swish}(W_1 \cdot \phi(\tau))\bigr)$$

- $\phi: \mathbb{R} \to \mathbb{R}^w$：sinusoidal positional encoding（参考 Transformer 原始论文）
- $W_1, W_2 \in \mathbb{R}^{w \times w}$：可学习权重
- 通过 adaptive RMSNorm 在每一层做 modulation（类似 DiT 的设计，参考 Peebles & Xie 2022）

### 2.5 Flow matching timestep 采样分布

放弃标准均匀 $\tau \sim \mathcal{U}(0,1)$，使用强调低 timesteps 的 Beta 分布：

$$p(\tau) = \text{Beta}\Bigl(\frac{s-\tau}{s};\, \alpha=1.5,\, \beta=1\Bigr), \quad s=0.999$$

intuition：低 timestep（$\tau$ 接近 1）对应精细化 denoising 步骤，对最终 action 质量影响大，所以多采样。$\tau > s$ 的区域排除，因为积分步长 $\delta > 1-s = 0.001$ 即可覆盖，理论支持 1000 步积分（实际推理只用 10 步）。

### 2.6 模型尺寸（附录 E）

| 组件 | width | depth | mlp_dim | heads | kv_heads | head_dim | 参数 |
|---|---|---|---|---|---|---|---|
| VLM (PaliGemma 2B) | 2048 | 18 | 16384 | 18 | 1 | 256 | ~2B |
| Action expert | 1024 | 18 | 4096 | 18 | 1 | 256 | ~300M |

- Action horizon $H = 49$（即 50 个 action token）
- 初始化：VLM 从 PaliGemma 预训练权重，action expert 在 post-training 起始时随机初始化

## 三、训练数据组成（精确配比）

### 3.1 Pre-training 阶段（280k steps，纯离散 token）

| 数据类型 | 缩写 | 描述 |
|---|---|---|
| Mobile Manipulator | MM | ~400 小时，~100 个真实家庭环境的移动双臂数据 |
| Multi-Environment non-mobile | ME | 固定单/双臂，在更多家庭环境采集（更易运输） |
| Cross-Embodiment lab | CE | 实验室多机器人多任务数据 + OXE 数据集 |
| High-Level subtask | HL | 对 MM/ME/CE 多阶段任务手动标注 subtask 描述，训练模型同时预测 subtask + action |
| Web Data | WD | image captioning (CapsFusion, COCO), VQA (Cambrian-7M, PixMo, VQAv2), object localization |

**97.6% 的 pre-training examples 不来自 mobile manipulator**——这是 transfer learning 的极致体现。

### 3.2 Post-training 阶段（80k steps，α=10.0）

数据筛选：
- MM + ME 数据中的成功 episode，并按长度过滤
- 保留 WD 维持语义视觉能力
- HL 数据中的 multi-environment 子集
- **新增 VI (Verbal Instructions)**：人类"language demonstrations"，专家实时用语言指挥机器人执行任务（选合适的 subtask 命令逐步推进）。这本质上是 high-level policy 的 demonstration data
- 移除 CE，聚焦 mobile manipulation

VI 只占 high-level mobile manipulation examples 的 ~11%，但对最终性能至关重要（见 ablation）。

### 3.3 Action 归一化策略

- 每个 action 维度按各数据集的 1% 和 99% quantile 归一化到 $[-1, 1]$（用 quantile 而非 min/max，抗 outlier）
- 维度对齐：统一到最大 action 空间维度，低维机器人 zero-pad
- Control mode token：在 prompt 中加入 `<control mode> joint/end effector <control mode>` 区分目标

## 五、实验结果

### 5.1 Real Home 评估（问题 1）

在 3 个完全未训练过的真实家庭中测试，每家做卧室 + 厨房清理任务，每任务 10 次试验。任务持续 2-5 分钟。结论：π0.5 在所有家庭所有任务上稳定成功。图 7a 展示了具体 rollout：
- Home 1：把物品放进抽屉
- Home 2：把盘子放进水槽
- Home 3：把衣服放进洗衣篮

模型先输出 subtask（蓝色文字，如 "pick up the cutting board"），再执行 low-level action。

### 5.2 泛化随训练环境数的 scaling（问题 2）

实验设置：
- 训练环境数：3, 12, 22, 53, 82, 104
- Post-training 40k steps，控制每个模型看到的 unique samples 数量一致（消除数据集大小变量）
- 在 mock homes 评估 4 个任务

关键对照实验（图 8）：
- **绿色虚线柱**：训练时**直接包含**测试家庭数据的 baseline 模型
- **104-location 模型（蓝色）**：从未见过测试家庭
- 两者性能**几乎相同**——证明 co-training recipe 成功 bridge 了 generalization gap！

进一步 ablation：
- 仅用 104 location MM 数据（无 web/HL co-training）：显著更差
- 仅用测试家庭数据（无 co-training）：也显著更差

**重要结论**：单靠 robot data scale 远远不够，必须 co-training with heterogeneous sources。

### 5.3 Language following 细粒度评估

任务设置（Fig. 14）：
- 5 个物体放桌面，其中目标物体距离最远（防止"无脑抓最近" shortcut），理论上随机抓取只有 20% 语言跟随率
- 两个场景：items in drawer / items in sink
- 测试 in-distribution 物体（见过类别新 instance）和 OOD 物体（漏斗、药瓶、烧烤打火机、护目镜等完全未见类别）

指标：
- **Language following rate**：是否选对了语言指定的物体
- **Success rate**：是否成功放到指定位置（drawer/sink）

结果（图 9）：随训练环境数增加，两者都提升，in-distribution 提升快于 OOD。

### 5.4 Co-training recipe ablation（问题 3，图 10/11）

在 mock home 4 任务上：
| Ablation | 影响 |
|---|---|
| no WD | 无显著差异（mock home 任务） |
| no ME | 显著下降 |
| no CE | 显著下降 |
| no ME or CE | 进一步下降 |

在 language following 上（图 11）：
- no WD：**OOD 性能显著下降**（WD 提供广泛物体知识）
- no ME / no CE：in-distribution 和 OOD 都下降

per-task breakdown（图 16）：
- **Items in Drawer**：对 WD/ME/CE 都敏感（需要广泛物体识别 + manipulation）
- **Dishes in Sink**：对 ME/CE 敏感，对 WD 不敏感（主要是 manipulation 策略）
- **Laundry Basket / Make Bed**：cross-embodiment 重要，对其他不太敏感

### 5.5 与 π0 系列比较（问题 4，图 12）

对比对象：
- **π0**：纯 flow matching，无 HL/WD，始终用 action expert
- **π0-FAST+Flow**：混合训练 recipe（FAST + flow），但只用 action data，无 HL/WD
- **π0.5**：完整 co-training + 混合 action 表示

结果：π0.5 显著超越两者，即使 π0 训练到 300k steps 也追不上。这验证两点：
1. FAST token pre-training 的 compute efficiency 优势（参考 Pertsch et al. 2025）
2. Co-training with HL + WD 提供不可替代的语义知识

### 5.6 High-level inference 的重要性（问题 5，图 13）

对比方案（都用 π0.5 low-level）：
| 方法 | 描述 | 性能 |
|---|---|---|
| Full π0.5 | HL + low-level 一体 | **最好** |
| implicit HL | 无 runtime HL 推理，但训练含 HL 数据 | 第二好（接近） |
| no HL | 无 HL 推理也无 HL 数据 | 显著下降 |
| GPT-4 HL | 用 GPT-4 zero-shot 作 HL | **最差** |
| human HL | 人类 oracle 作 HL | 被 full π0.5 超越 |
| no VI | 移除 verbal instruction 数据 | 显著下降 |
| no WD | 移除 web data | 显著下降 |

**反直觉发现**：implicit HL（不显式做 high-level 推理，但训练时含 HL 数据）性能接近 full π0.5，远超 no HL。这表明**co-training recipe 本身就让模型隐式学会 subtask structure**，显式 inference 只是锦上添花。

GPT-4 zero-shot 表现最差：证明 VLM 必须用 in-domain robot data fine-tune 才能成为有效的 HL policy。

per-task breakdown（图 17）：
- Items in Drawer / Dishes in Sink：high-level inference 关键（no HL 大幅下降）
- Laundry Basket：对 HL 选择不敏感（任务较短）

## 六、Intuition 构建：为什么这套 recipe 能 work？

### 6.1 异构数据 = 多层级归纳偏置

不同数据源提供不同抽象层级的知识：
- **WD (web)**：物体语义、视觉概念、属性关联（"漏斗是漏斗"）→ 帮助 OOD 识别
- **CE (lab cross-embodiment)**：基础 manipulation primitives（抓、放、推）→ 帮助 in-distribution 物理交互
- **ME (multi-env static arm)**：环境多样性 + simpler embodiment → 提供更广的 household scene coverage
- **MM (mobile)**：目标 embodiment 的直接经验 → 教会底盘移动 + 双臂协调
- **HL (subtask)**：任务结构 → 教会长程推理
- **VI (verbal instruction)**：人类示范"如何分解任务" → 教会任务规划策略

这种层级知识互补，单独任何一个都不够。

### 6.2 离散 token vs 连续 flow 的分工

- **离散 FAST token (pre-training)**：
  - 训练快（next-token prediction 的成熟工具链）
  - 与 VLM 共享 vocabulary，language-following 能力强
  - FAST 基于 DCT 压缩，能高效编码 50-step action chunk
- **连续 flow matching (post-training)**：
  - 表达 multi-modal action distribution（同一 observation 可能有多种合理 action）
  - 10 步 denoising 即可实时推理，无需 autoregressive 50 步解码
  - action expert 独立参数，专注 action 生成

**关键 mask 设计**：两套表示在 attention 中隔离，避免互相"作弊"（FAST 不能偷看 flow 的中间结果）。这是混合表示能稳定训练的根基。

### 6.3 高级推理 = 测试时计算

π0.5 的 hierarchical inference 类似 o1 风格的 test-time compute（参考 OpenAI o1 system card, arxiv 2412.16720）：
- 模型在执行前先"思考"一步：根据当前 observation 和高层 prompt，输出语义 subtask
- 然后 condition 在 subtask 上输出 action
- 这把"长程任务"分解成"短程 subtask"序列，每个 subtask 由 low-level policy 执行
- 训练数据中 HL 标注 + VI 示范教会模型这种 decomposition 能力

implicit HL 也很强说明：模型内部已学会 subtask structure，即使不显式输出 subtask token，相关信息也已编码在 hidden state 中指导 action 生成。这呼应 chain-of-thought 在 LLM 中的发现——CoT 训练数据让模型即使 implicit 推理也受益。

参考：
- Chain-of-thought：https://arxiv.org/abs/2201.11903
- o1 system card：https://arxiv.org/abs/2412.16720
- Embodied CoT (ECoT)：https://arxiv.org/abs/2407.08693

## 七、与相关工作的位置

### 7.1 VLA 谱系
- **RT-2** (Zitkovich et al. 2023)：首次把 VLM fine-tune 为 VLA，纯离散 action token
- **OpenVLA** (Kim et al. 2024)：开源 7B VLA
- **π0** (Black et al. 2024)：引入 flow matching + action expert，dexterous mobile manipulation
- **RDT-1B** (Liu et al. 2024)：diffusion foundation model for bimanual
- **CogACT** (Li et al. 2024)：cognition + action 协同
- **π0.5**：在 π0 之上加 co-training recipe + hybrid action representation + hierarchical inference

### 7.2 通用 robot policy 数据集
- Open X-Embodiment (OXE)：跨 embodiment 大型数据集
- DROID：大规模 in-the-wild manipulation
- BridgeData V2：通用 robot learning
- AgiBot World Colosseo：大规模 manipulation 平台
- π0.5 用 OXE 作为 CE 数据的子集

### 7.3 Hierarchical robot reasoning
- SayCan (Ahn et al. 2022)：LLM 作高层 planner + affordance
- RT-H (Belkhale et al. 2024)：language action hierarchies
- Hi Robot (Shi et al. 2025)：hierarchical VLA for open-ended instruction
- ECoT (Zawalski et al. 2024)：embodied chain-of-thought
- π0.5 区别：**同一模型**做 high-level 和 low-level，类似 in-context CoT 而非双模型分离

### 7.4 FAST action tokenizer
基于 DCT (Discrete Cosine Transform) 的压缩式 action 编码（Pertsch et al. RSS 2025）：
- 把 50-step action chunk 压缩为少量 token
- 比直接 bin 每个 action 维度的离散化（如 RT-1 的 256 bins）信息密度高得多
- 与 VLM 共享 next-token prediction 框架，训练高效
- π0.5 在 pre-training 用 FAST，post-training 切换到 flow matching，得到两套方法各自优势

参考 FAST：https://arxiv.org/abs/2501.09747

## 八、Limitations 与未来方向

论文诚实地列出 limitation：
1. **Persistent failure modes**：陌生抽屉把手、难打开的柜门
2. **Partial observability**：机械臂遮挡需要擦拭的污渍
3. **High-level inference distraction**：重复开关抽屉（陷入 loop）
4. **Prompt 复杂度受训练数据限制**：当前只能处理简单 high-level prompt
5. **Context window 有限**：跨房间任务、长期记忆尚不支持

未来方向猜测：
- 更丰富的 context + memory（如 video-conditioned、spatial memory module）
- 更复杂的多模态人类指令（demonstration video、sketch）
- 加入更多 transfer 源（sim data、simulation physics priors）
- Verbal instruction 这种 "language demonstration" 是新监督范式，可大规模扩展
- RL fine-tuning 后处理 persistent failure modes
- Cross-embodiment 进一步扩展到 humanoid、四足、灵巧手

## 九、关键 takeaways（build intuition 总结）

1. **Open-world generalization 不靠 robot data scale，靠 heterogeneous co-training**。104 个家庭训练 + co-training 达到与"测试家庭直接进训练集"相同的性能，证明 recipe 比数据更关键。

2. **离散 + 连续 action 双表示训练**优于单一方法。FAST 提供 compute-efficient 预训练 + 强 language following，flow matching 提供表达力 + 实时推理。关键在 attention mask 设计让两者独立训练。

3. **Hierarchical inference 用同一模型实现**——high-level "think" 然后 low-level "act"。这类似 CoT/test-time compute，但生成 subtask 后立即执行 action，而非纯语言推理。

4. **Implicit HL 几乎和 explicit HL 一样好**——只要训练数据中含 HL 标注，模型内部就学会 task structure。显式 inference 是锦上添花。

5. **VI (verbal instruction) 数据虽然只占 11% 但至关重要**。人类用语言指挥机器人 = high-level policy 的 demonstration data。这是新的监督范式。

6. **GPT-4 zero-shot 作 HL 最差**——证明 in-domain fine-tuning 必要。Web-scale VLM 知识必须用 robot data 蒸馏才能用于实际 control。

7. **97.6% pre-training 数据不是目标 embodiment**——但通过 VLM 框架的统一 sequence modeling，knowledge 成功跨 embodiment、跨模态迁移。这是 transfer learning 在 robotics 的实证胜利。
